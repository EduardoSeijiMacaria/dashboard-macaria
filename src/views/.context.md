The two pages of the app: the dashboard and About. The page comes from the URL hash (`#/sobre`), with no router library. `DashboardView.vue` reads state and actions from `useAuditDashboard` and arranges the page as a flex column that fills the window height: `AppHeader`, `SettingsPanel`, `main` (filters, summary and refresh control, and the issue table with its loading, error, empty, and no-match states), and `AppFooter`, which stays at the bottom without a fixed position. The open row shows `IssueDetails`.

## Summary

- DashboardView.vue — the page shell (header, footer) and the dashboard template; it keeps the dashboard mounted and hidden while About shows
- AboutView.vue — the About page: introduction, capability cards, numbered steps, result states, a short privacy block, and the developer card

## Constraints

- Issue text MUST render through interpolation. The view MUST NOT use `v-html`.
- The view MUST NOT ask for a token or a repository. Both come from `.env`.
- Opening or closing the settings panel MUST NOT start a request or change the loaded data.
- Changing page MUST NOT unmount the dashboard. Filters, loaded data, and the token in memory MUST stay.
- The About capability cards MUST list only features that exist. The text MUST show no internal rule code.
- The About text is for people who open the dashboard. It MUST NOT show `.env`, token, or permission details.
- The contact MUST come from `services/developerInfo.ts`. The view MUST NOT invent an address.
