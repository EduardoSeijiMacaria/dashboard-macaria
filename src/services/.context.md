Side-effect helpers used by the dashboard. They cover default config and filters, the embedded `.env` values, issue classification, sync settings checks, date handling, filtering, metrics, per-issue audit state, error messages, and the GitHub REST client.

## Summary

- classifyIssue.ts — pure `classifyIssue`: native type name first, then fallback labels; returns the category and its origin (`type`, `label`, `unclassified`)
- config.ts — `defaultConfig` (rule enable flags and severities, and `classification` names for types and fallback labels, `requiredFields` (name, empty message, expected value), `optionalFieldNames`, `allowedMilestoneNames`, and `startDate`), `defaultFilters`, and `githubToken`, `repositoryUrl`, and `projectNumberSetting` (embedded by `vite.config.ts`; empty under test)
- dates.ts — calendar-date helpers and `formatDateTime` in `America/Sao_Paulo`
- calculateMetrics.ts — pure `calculateMetrics`: totals, error and warning issue counts, clean, partial, and finding count
- developerInfo.ts — `developerInfo` (developer name and the optional contact channel; the place to set the contact) and `findUsableContact` (accepts only `https:` and `mailto:` links)
- appError.ts — `AppError`, an error that carries a message key with its data (`messageRef`)
- errorMessages.ts — `isAbortError` and `toMessageRef` (the message key of any thrown value)
- filterIssues.ts — pure `matchesFilters`: search, assignee, category, severity, view, and date range for one issue
- githubIssues.ts — shape check for a GitHub issue response and its mapping to `AuditIssue` (reads `type.name`, classifies)
- groupByIssueId.ts — groups findings or not-evaluated results by issue ID
- issueAuditState.ts — pure `getIssueAuditState`: `problems`, `not-evaluated` (an unchecked rule, or category Outro), or `clean`
- githubProject.ts — reads Project field definitions and items from the API responses (`toProjectFieldDefinitions`, `toProjectItem`: only `Issue` items, related by `content.id`) and `toProjectValue` (`null` is empty; text, option, number; an unknown shape is an error)
- projectFields.ts — `listCollectedFieldNames`, `collectProjectData` (definitions, then items or one item), pure `mergeProjectFields` (one item per issue by `content.id`; outside the Project, not found, and query error states), `markProjectFields`, and `getFieldStateAfterFailure`
- typeGuards.ts — `isRecord`
- github.ts — `GitHubClient`: paginates repository issues, lists Project fields and items (follows the `Link` header; refuses a link outside `api.github.com`), `getProjectItem`, `GitHubApiError` (an `AppError` that also carries the HTTP status), `getIssue` (one issue by number; 404 and 410 give an issue message), maps through `githubIssues.ts`, retries up to 3 times (403 or 429 with a wait hint, and 5xx), and maps 401, 403, and 404 to message keys; `waitWithAbort` is the default wait
- syncSettings.ts — `parseRepositoryUrl` (owner and repository from the URL) and `parseProjectNumber` (empty means no Project), and `requireGithubToken` (rejects an empty token)

## Constraints

- GitHub calls MUST be read-only. The client sends only GET requests and never writes to GitHub.
- A retry MUST NOT exceed 3 attempts. A single wait MUST NOT exceed 30 seconds. A 401 or a 404 MUST NOT be retried. An abort MUST cancel the wait.
- The token MUST NOT appear in a log or an error message. It goes only in the `Authorization` header.
- Type names and label names for classification MUST come from `defaultConfig.classification`. They MUST NOT appear as constants elsewhere. Classification MUST NOT read the title.
- Date comparisons MUST use calendar dates in `America/Sao_Paulo`.
