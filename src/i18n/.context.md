Internationalization for the interface in three languages: `pt-BR` (default and fallback), `en`, and `es`. It uses `vue-i18n` through one shared instance. Components, rules, and errors never hold a translated text: they hold a message key and its data.

## Summary

- index.ts — the `vue-i18n` instance (`legacy: false`, fallback `pt-BR`), `getActiveLocale`, and `setActiveLocale`
- locales.ts — the supported languages, their own names, `resolveInitialLocale` (saved choice, then the browser language, then `pt-BR`), and the `localStorage` read and write (key `qa-dashboard-locale`)
- messageKeys.ts — `MessageKey` (every dotted key of the pt-BR catalog) and `MessageSchema` (the shape the other catalogs must have)
- translate.ts — `t` (key, data, and a count for plurals), `translateMessage` (a key with its data), `translateText` (a literal or a key), `formatList`, and `formatNumber`
- messages/ — one catalog per language, with the same keys: `pt-BR.ts`, `en.ts`, `es.ts`

## Constraints

- Every catalog MUST have exactly the same keys. The type `MessageSchema` and `tests/i18n.test.ts` enforce it.
- Text that comes from the GitHub MUST NOT go into a catalog or through a translation: issue titles, assignees, labels, milestones, issue types, Project names, field names, option values, and dates inside text. Pass them as data (`{name}`) into a message.
- A message that contains a `|` MUST write it as `{'|'}`, because `vue-i18n` reads a bare `|` as a plural separator.
- Code MUST NOT test a translated text. Rules, filters, and comparisons use keys and raw values.
- A language that is not supported MUST fall back to `pt-BR`. The interface MUST NOT show a key.

## Guidance

- Add a new text to all three catalogs in the same change.
- A rule or an error SHOULD return a `MessageRef` (`{ key, params }`). The screen translates it with `translateMessage`.
